## Component boundaries

1. `delta/delta-common` owns the pure Java registration marker and commit-action correlation protocol. It contains no Spark, Kernel, Hadoop, Gravitino core, or test-fixture dependency. Keep existing Java package names and wire encoding stable when moving the previously qualified implementation. Main bytecode remains Java 8 compatible.

3. An optional Spark 3.5 Delta adapter composes native DeltaCatalog. Its runtime consumes the shared protocol and ordinary Gravitino client APIs without depending on server provider/test jars. Default Spark artifacts remain free of Delta dependencies.

## Server behavior

Use existing managed entity storage and complete-row optimistic comparison. Native I/O occurs outside entity update callbacks. Preserve registration ID, governance owner and audit history during publication/replacement. Never replay CREATE successfully on an already published row: the existing create hook would reset ownership.

Catalog administrators are trusted to configure immutable warehouse/adoption roots, credentials and recovery principals. Ordinary schema/table requests cannot override these. Use existing secret references and masked properties; disable credential backfill. Reader resources must be isolated per catalog even when classloaders are pooled.

Normal publication belongs to the current operation actor after its completed native transaction, with exact durable operation and native commit evidence. Recovery requires authenticated durable HANDOFF attestation tied to the operation and writer run; it records the platform controller's assertion that the writer was stopped and restart suppressed. It is not an independently verified S3 fence. Privileged paths reject anonymous identities and disabled authorization.

STATUS provides an authenticated receipt for a known identifier through the existing alter-table endpoint, including pending entries hidden from normal discovery. A read-only token/run-bound STATUS form supports a lost initial POST reply when the client does not know its allocated numeric ID; it still requires current operation actor or privileged recovery authority and existing REST authorization, and never weakens expected-ID checks on mutations. Missing initial ownership may require privileged administrative STATUS. ADOPT is privileged, observational registration of a known admitted native location; it reads native schema/UUID/protocol and does not rewrite Delta history or mutate Glue. Automatic Glue enumeration is outside this increment. An absent native registration marker is normal. A decodable foreign marker is immutable prior provenance, never current adoption authority; do not expose its token. Initial admission rejects malformed or unknown marker encodings with a sanitized error and makes no native repair. Adoption requires controlled cutover and platform admission for location ownership; per-row CAS does not enforce global alias uniqueness.

ADOPT first stores an `ADOPTING` entry, then publishes through PUT after the existing ownership hook has established an owner and fresh native observation confirms the same table lineage. Its evidence is `EXISTING_NATIVE_SNAPSHOT`, never a synthetic matched CREATE. Exact pending POST replay is the narrowly scoped ownership-hook repair path; published POST replay always fails. Production clients must use STATUS after an uncertain POST result and establish original request completion or drain before repair/replay. Gravitino's create ownership hook executes outside provider CAS, so the no-core design cannot promise atomic ownership safety for arbitrary overlapping POST retries, publication and owner transfers. Do not add a purported atomic owner-repair command over the existing unconditional owner setter.

An authorized new modifier becomes the actor of a new replacement operation while the governance owner remains unchanged. Refresh begins only from a published row, reads native metadata outside the store callback, and compares the complete original row before updating. Same-native-ID advancement retains operation correlation and unchanged column identities; unexpected native-ID changes quarantine rather than silently adopt another table. Preserve native column mapping identity when available, and exact unchanged logical names otherwise; unmapped drop/re-add between observations cannot establish physical-column lineage. Persist a digest of full native configuration and an explicit safe subset, avoiding wholesale sensitive configuration in receipts or durable table properties.

ABORT after authenticated handoff retains an `ABANDONED` tombstone. It abandons registration without claiming rollback or noncommit, restores no previous replacement publication on missing logs, and never makes a location safe for reuse. Physical purge, unguarded name reclamation, rename and cascade over hidden registrations remain gated until separately qualified lifecycle semantics exist.

Checkpoint-aware metadata reading must replace the prototype's bounded JSON-history reader before production adoption. Native schema metadata is preserved losslessly alongside its Gravitino type projection. Kernel compatibility and feature coverage require explicit tests against both supported patches; unsupported protocols fail explicitly, never silently downgrade.

Choose a single isolated, package-private Kernel 3.3 metadata adapter. Public snapshots do not expose native table ID/configuration/protocol, while a public checkpoint parser would duplicate checkpoint discovery and replay. Guard exact API/defaults runtime versions and implementation class; copy values immediately without exposing internal types. This intentionally replaces the previous bounded milestone's public-Kernel-only design restriction, which was not a user restriction. Any Kernel upgrade requires renewed compatibility tests.

Kernel 3.3 cannot discover unbackfilled coordinated commits. Reject active or malformed coordinated-commit configuration explicitly before reporting current metadata or publication evidence. A conforming conversion commit is filesystem-visible, making that guard possible; it is not a detector for arbitrary malformed logs. Coordinated-commit support requires a later coordinator-aware reader and is not included in this reader's compatibility claim. Other writer-only features remain observable when they do not alter log discovery.

Own a fresh Hadoop UGI Subject per provider instance and run all eager and lazy Kernel I/O within its scope. Drain reads before closing only that Subject's cached filesystems. This addresses pooled catalog classloaders without core edits or global Hadoop mutation. Raw native configuration is internal and may contain sensitive operational values; publish only an explicit safe subset.

## Spark behavior

Keep native DeltaTableV2 and native write paths. Carry full registered identity in a nonpersisted native table descriptor for later Ranger scans. Such descriptors can trigger native UpdateCatalog hooks; participating sessions require spark.databricks.delta.catalog.update.enabled=false for their lifetime, with entry/commit validation and collision-sentinel qualification. This mutable SQLConf is a deployment invariant, not an arbitrary-code configuration lock. Native staging/outer ALTER remain path-based and never register a second session-catalog table. An inert staged descriptor may expose schema and capabilities before reserving. At query writer construction, reserve with the resolved native query-schema normalization; at schema-only commit, reserve with the exact declared schema. Schema-only CREATE OR REPLACE uses native stageReplace for an existing name and stageCreate for an absent name after authoritative Gravitino lookup and reservation. Do not blanket-normalize schema-only NOT NULL constraints.

Native column mapping creates assign physical names during commit; the v1 exact-schema marker cannot predict them. Preserve v1 behavior and add a closed, versioned semantic schema contract before claiming mapped CREATE/REPLACE support. That contract binds the required logical schema and admitted native feature policy, permits only specifically validated engine-generated fields, and retains exact actual-action-to-Kernel-schema equality. It is correlation data, not a signature or bearer credential. Generated expressions, defaults and identity columns require separate native entrypoint tests; the source evidence does not justify blanket stripping of their metadata.

Operator status/recovery must use production client transport, not raw-store fixtures. Resolve current request identity through the existing catalog manager, without closing shared clients or pinning the first actor. Keep a distinct read-metadata transport seam for a later scoped metadata credential, so Ranger-only column grants do not force broad end-user Gravitino table grants. Registration mutation actor and authenticated Ranger query subject remain separate from that credential. Qualify production jars in fresh Spark JVMs and a real provider server; previous test classpaths do not establish distribution correctness.
