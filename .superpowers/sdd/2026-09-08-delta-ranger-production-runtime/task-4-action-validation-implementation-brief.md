## Retained registration validation

Add the real binding-owned ValidateRetainedBinding operation together with its
actual consumer. Validate the retained descriptor/relation/index/log and catalog
lease first. Read a fresh scoped PUBLISHED observation for its canonical name.
Require the same registration incarnation, location, native ID and logical schema.
Inspect the current native head through the retained exact log inside this typed
operation, never by loading a replacement table by name/path. Preserve exact raw
native schema, ordered partitions, protocol and column-mapping compatibility.
Compare fresh metadata observations before/after native inspection, reject
observed drift and finish with the same owned lease still live.

A data-only native version advance between actions is compatible with the same
registration incarnation and schema; the retained plan may keep its previously
selected snapshot. Do not promise latest rows. Reject regressions and metadata
versions newer than the verified native head, and reject observed within-bracket
version drift. Preserve ordinary-load exact-publication checks where appropriate;
do not silently weaken the existing load protocol to accommodate action reuse.

## Complete decision validation

Expose an action-specific validator on the actual original receipt. Validate the
same Spark session, captured configuration, authenticated short user and immutable
groups, complete engine/role stamps, all original scan occurrences and bindings.
Choose one fresh immutable Instant for the whole action batch. Authorize all
original access resources across all catalogs before reevaluating any row-filter
or column-mask decision. Compare every semantic decision to the captured rewrite,
including NONE and absent filters. Do not rewrite the retained plan or run a user
physical child while validating. Finish registration/metadata work before final
engine, subject, configuration and liveness checks. Reject observed drift.

Keep analysis receipt checks and action checks explicit: analysis replay has its
existing structural responsibility; action reevaluation must not silently replace
it or manufacture a new receipt. Preserve duplicate self-join obligations and
original obligations whose scans were optimized away. All authority remains
driver-only, non-product and inert after serialization.

Pair unchanged controls with access revoke, same-number publication replacement,
role-only change, subject/groups change, time-dependent changed filter/mask with

drift, two-catalog and duplicate-occurrence checks. Prove a common action Instant
and all-access-before-any-decision ordering. Include data-only native advancement
positive and within-bracket drift negative. Failures must identify the actual
validator boundary. Component calls are not retained collect/collectAsList proof.
