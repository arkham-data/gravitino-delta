# Task 4: production physical boundary and native provenance

Design against `f1bf2f193048771fb7e1dce0611daa5c344e9d09`, 2026-09-21. This document supplements `task-4-reuse-enforcement-design-review.md` and `task-4-reuse-mechanics-report.md`; it does not repeat or extend their qualification claims. Only this document was written. No production/test source edits, Gradle, JVM, live service, Docker, or commit operations were performed. No callable claude-mem/mcp-search tool was exposed; the prior reports, pinned Delta sources, current production/tests, and official Spark sources were inspected instead.

**Implement one visible, non-codegen unary root for admitted user SELECT collection. Classify native metadata using sealed operation-owned provenance captured during valid native admission. Absence of a user receipt is always insufficient to classify a plan as native.** The supported action contract remains repeated `Dataset.collect` and `collectAsList`. User AQE is explicitly unsupported; production configuration must not be changed to make it pass.

## 1. Source facts that determine the integration

`DeltaRangerReadRule.apply/check/prepare` currently call the Boolean `internalMetadata`; the physical extension does not exist. `internalMetadata` depends on `NativeScope` for action/stats RDDs and exact snapshot aggregates/bindings. It also accepts exact-class `DeltaLogFileIndex` leaves outside scope, and some empty encoder-binding plans outside scope. Those latter routes must not become an executable no-receipt fallback. `registerSnapshot` captures state RDD identity/output, but stats admission currently records only a schema. The existing schema-matching tests explicitly accept unrelated empty RDDs inside scope; they must change for persisted executable provenance.

Spark planning creates more than one copy. `QueryExecution` clones the logical tree before planning and the physical tree before preparation. The preparation pipeline invokes columnar rules before codegen collapse and exchange reuse. Thus logical object identity alone cannot bind a final physical plan, and a visible unary child is necessary to retain tail-pass traversal. [Spark 3.5.4 QueryExecution, `sparkPlan`, `executedPlan`, `preparations`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/QueryExecution.scala).

`SparkStrategies.plan` sets the planned subtree's logical link, unwrapping `ReturnAnswer`. A physical node can inherit an ancestor link; it need not point to its own logical leaf. Links are evidence of origin, not authorization. [Spark 3.5.4 SparkStrategies, `plan`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/SparkStrategies.scala). `SparkPlan.logicalLink` reads direct then inherited tags; `setLogicalLink` preserves descendant direct links. Synthetic physical nodes can lack both. [Spark 3.5.4 SparkPlan, `logicalLink`, `setLogicalLink`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/SparkPlan.scala).

Spark tree cloning and replacement normally copy tags, but `copyTagsFrom` copies only when the destination tag map is empty. Tags can therefore disappear, move to a replacement, or be deliberately copied onto another tree. Do not assume universal propagation or treat an opaque tag alone as a capability. Structural changes need binding verification; exact Spark clones retaining the same backing objects must remain admissible. [Spark 3.5.6 TreeNode, `copyTagsFrom`, `withNewChildren`, `makeCopy`, `clone`](https://raw.githubusercontent.com/apache/spark/v3.5.6/sql/catalyst/src/main/scala/org/apache/spark/sql/catalyst/trees/TreeNode.scala).

The existing extension must register **both** callbacks on one `ColumnarRule`: classify and capture the incoming tree before transitions, then verify the transformed tree and wrap its user root afterward. Post rules run in reverse extension order. New row/columnar transitions are constructed around existing children and need not themselves retain a logical link. [Spark 3.5.4 Columnar, `ApplyColumnarRulesAndInsertTransitions.apply`, `insertTransitions`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/Columnar.scala).

Native AQE requires an explicit inspection path. `AdaptiveSparkPlanExec` is a leaf exposing `inputPlan`; `QueryStageExec` is a leaf exposing `plan`. Ordinary `children` traversal misses their executable contents. Inspect those fields without executing/materializing stages. [Spark 3.5.6 AdaptiveSparkPlanExec, constructor](https://raw.githubusercontent.com/apache/spark/v3.5.6/sql/core/src/main/scala/org/apache/spark/sql/execution/adaptive/AdaptiveSparkPlanExec.scala), [Spark 3.5.6 QueryStageExec, `plan`](https://raw.githubusercontent.com/apache/spark/v3.5.6/sql/core/src/main/scala/org/apache/spark/sql/execution/adaptive/QueryStageExec.scala). Native stage callbacks must return the same root category: AQE requires shuffle/broadcast exchanges to remain exchange roots after columnar rules. User stage wrapping is outside this design. [Spark 3.5.4 AdaptiveSparkPlanExec, `postStageCreationRules`, `newQueryStage`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/adaptive/AdaptiveSparkPlanExec.scala).

## 3. User physical ticket and exact scan lineage

Use separate types, for example `UserPhysicalTicket(receipt, preparedOccurrences, physicalWitness)` and `NativePhysicalTicket(operation, nativeWitness)`. A sealed sum type prevents confusing a native metadata ticket with an original-access receipt. The user ticket references the entire parent receipt, including every original occurrence and owning engine in a join.

Spark's tag map is **not transient**. Tags must therefore carry only an inert serializable `DriverWitnessRef` whose authority payload is transient, with constant/redacted display and no principal, engine, source location or receipt fields serialized. Keep the actual ticket in that driver-only payload; a deserialized reference has no authority and fails closed if used for admission. Use the same rule for logical tags, since physical logical links can retain logical trees. Merely marking the guard's context transient does not prevent a receipt in child tags from reaching task serialization. [Spark 3.5.6 TreeNode, `tags`](https://raw.githubusercontent.com/apache/spark/v3.5.6/sql/catalyst/src/main/scala/org/apache/spark/sql/catalyst/trees/TreeNode.scala).

Before the companion's native preparation, bind each original logical scan occurrence to the receipt and its exact original `TahoeLogFileIndex`. Preserve occurrence identities separately from the index: self-join occurrences can legitimately share backing native objects. Override the existing anonymous `PrepareDeltaScan`'s protected methods:

1. `getDeltaScanGenerator(index)`: keep the exact native `Snapshot` check and call the revised `registerSnapshot(index, snapshot, operation)`.
2. `getPreparedIndex(preparedScan, fileIndex)`: call `super`, record the returned `PreparedDeltaFileIndex` by reference together with the exact input index and `preparedScan.scannedSnapshot`, then return that same instance.
3. After native `apply` returns, bind each resulting `LogicalRelation` to its original occurrence using descriptor/output identity and the recorded original-to-prepared index transition. Check occurrence coverage and reject a missing or ambiguous match. Explicitly install the completed root and occurrence evidence; do not rely on Delta's tag copying alone.

This is an existing protected non-final seam in pinned `task-3-evidence/pinned/org/apache/spark/sql/delta/stats/PrepareDeltaScan.scala`, `getPreparedIndex`. Pinned `DeltaTable.scala`, `DeltaTableUtils.replaceFileIndex`, copies `LogicalRelation` and `HadoopFsRelation` while replacing the location. Comparing a physical file scan to the original index would reject correct queries; accepting a newly reconstructed same-path index would weaken the binding.

In the pre-columnar callback, obtain candidate root/occurrence receipts through logical links across the tree, then verify all actual file leaves against the completed bindings. `FileSourceScanExec.relation.location` must be one of the exact prepared indices issued above, and its output/required schema must be a valid planned projection of that occurrence. Check catalog descriptor and snapshot lineage as corroboration, not path authority. Unknown file/RDD/command leaves reject. A node's inherited logical link cannot cover an unrelated leaf. Root receipt loss may be recovered only from a complete, unambiguous set of bound occurrence evidence for the same parent receipt; no default receipt and no arbitrary first-child selection.

Handle an optimized empty user result explicitly: an admitted false predicate may eliminate every file scan. A receipt-bearing, non-streaming, empty `LocalRelation`/`LocalTableScanExec` can receive an `EmptyUserResult` witness if it has the expected output and exactly zero local rows. Retain and validate the entire original receipt despite having no physical scan obligations. It still gets the user collection guard and user AQE/cache restrictions; it never becomes native. Reject nonempty local replacements and receipt-less empty plans. Add a real constant-false predicate positive control and a stale repeated empty-result denial. For other eliminated/merged occurrences, require an explicit verified optimization mapping rather than silently dropping original receipt obligations.

Attach the resulting pre-transition physical witness to existing nodes sufficient to recover it after transitions, with a single plan-owned ticket referenced by those tags. The post callback gathers candidate tickets from the actual tree, verifies one consistent user parent and complete occurrence coverage, verifies the allowed row/columnar wrappers, and installs the guard above the whole tree. Do not use a mutable `lastPlan` field shared between concurrent planning calls. If propagation is missing or conflicting, reject explicitly.

The physical witness records node kinds, expressions/output bindings, source identities and child edges. At collection entry verify the final child against the witness while allowing only the known tail rewrites: whole-stage/input-adapter wrappers and qualified exchange reuse. `ReuseExchangeAndSubquery` can replace an exchange with `ReusedExchangeExec`; inspect its referenced exchange and validate its output remapping. Count logical scan obligations by occurrence, not unique physical scan objects, so deduplication does not discard a self-join authorization obligation. Reject executable subqueries for the current admitted user grammar. [Spark 3.5.6 ReuseExchangeAndSubquery, `apply`](https://raw.githubusercontent.com/apache/spark/v3.5.6/sql/core/src/main/scala/org/apache/spark/sql/execution/reuse/ReuseExchangeAndSubquery.scala).

Do not implement physical witness validation as plan-text, `sameResult`, canonicalized equality alone, a plan ID, file path, or tag equality. Copying a valid marker onto a different source, altered occurrence inventory or altered retained expression tree must reject. A byte-for-byte equivalent Spark clone sharing the authorized backing identities is allowed; trying to distinguish its origin from an identical trusted-code copy is outside the launcher trust boundary.

## 4. Native operation protocol that survives scope closure

### Owner and state

Replace an ambient list of indices with a private `NativeOperation` containing an unguessable identity, session identity, purpose, owner and a finite set of qualified backing objects. Supported purposes are `LoadNamed(PublishedObservation)`, `PrepareScans(UserReceipt, bindings)` and `ValidateRetainedBinding(binding)`. No caller can create a production operation from a bare path, schema, UDF class name, or missing receipt.

The registration designer supplies the immutable pre-observation before ordinary load. Its scope must cover `super.loadTable`, its native head check, the actual returned table's snapshot access, and `toBaseRelation`. After the outer registration/native checks succeed, seal the operation's completed owner binding. Failure marks all its issued tickets invalid. Successful close removes the ThreadLocal and freezes issuance; it does **not** erase already sealed provenance needed by delayed physical planning. Do not hold a strong global map of plans/snapshots. Tickets are retained by their plans, with weak identity lookup only where required for cached descriptors/RDDs and bounded operation ownership/lifecycle.

A complete native log-read ticket may execute while a valid load operation is active: native reads are necessary to finish the load. This is distinct from a pending RDD candidate, which must never execute. Neither ticket authorizes a user data scan or bypasses the later completed registration and original-access checks.

### Finite routes and issuance

| Native route | Evidence captured during valid admission | Later executable evidence |
| --- | --- | --- |
| Native JSON/checkpoint log read | Active load/scan operation; exact `DeltaLogFileIndex` class, matching format, exact concrete fs/index objects, qualified log filenames, log root matching the operation's owner; snapshot/log object when available | Same captured backing fs/index identities plus qualified logical/physical recipe and operation owner. Ordinary JSON/Parquet relation never qualifies, including a file under `_delta_log`. |
| State reconstruction | Typed log-read inputs owned by the operation; admitted native object operators/expressions; capture actual function objects in reconstruction nodes in addition to the existing UDF origin checks | Complete native recipe and leaf bindings, including exact captured functions. A native class name or stats schema is insufficient. |
| Snapshot cached state | Enter a capture phase for a specific `(index, snapshot)` before `snapshot.stateDF`; allow analysis-only candidates during the getter's reentrant analysis; on return obtain its analyzed `LogicalRDD` | Seal only the exact returned RDD object and full output attributes, tied to that snapshot/index/owner. Candidate RDDs not matched to the returned lineage are discarded. |
| Parsed stats cache | After state registration, enter a separate capture phase for the same snapshot before public `snapshot.withStats`; capture its returned analyzed `LogicalRDD` similarly | Exact stats RDD/output identity, expected stats schema, and snapshot ownership. No arbitrary same-schema stats RDD exemption. |
| Snapshot aggregate | Existing exact aggregate specification over the sealed state RDD, including the admitted pruned-child and normalized typed-null variants | A typed aggregate witness retaining exact input/output lineage and finite specification, usable without consulting a live ThreadLocal. |
| SnapshotState encoder binding | Existing resolved/bound encoder equivalence and exact output sequence associated with that native aggregate | Analysis-only binding evidence. Its empty local relation is not a native executable cache or a user-data leaf. |

Pinned `StateCache.scala` explains the RDD capture order: `CachedDS` obtains `qe.toRdd.map(_.copy())`, persists it, then constructs `LogicalRDD(qe.analyzed.output, rdd)` through `Dataset.ofRows`. That Dataset construction reenters analysis before `snapshot.stateDF` returns. Consequently a design that insists the RDD was already registered before every analysis callback is circular. The analysis-only candidate phase resolves this without granting executable permission based on schema. It must not perform physical planning of that candidate. The underlying reconstruction query has its own completed log-read provenance and may execute to construct the cache.

Pinned `DataSkippingReader.scala` exposes public final `withStats`; its cache uses `StateCache`, and `withStatsInternal0` is derived from `allFiles`. Capturing it eagerly inside `registerSnapshot` is a deliberate additional native planning step, not a new SQL surface. It must be qualified to show it does not recurse into `computedState` or unrelated user execution. `Snapshot.scala` exposes `stateDF`; `SnapshotState.scala` computes its aggregate from that state. These source facts identify a feasible public seam but do not replace a runtime test.

Keep empty `SingleAction`/`Row` encoder-binding analysis helpers available only as analysis-only routes, with no executable native ticket. Their current presence outside scope is not evidence that an arbitrary empty local physical plan is internal. Likewise, do not persist the current generic schema-based action RDD predicate. Existing tests accepting fabricated state/stats RDDs inside scope must become explicit analysis-only or rejection tests; real snapshot controls must still pass.

### Classification after scope

The physical classifier reads sealed native witnesses; it must never rerun `internalMetadata(logicalLink)` hoping the scope is still active. Revalidate each witness against the linked logical subtree and actual physical backing leaves. Qualified optimizer changes require explicit finite recipe handling; tag transfer by itself cannot admit new functions, leaves or aggregates. Mixed native and user leaves, different owning operations without an explicitly composed owner, analysis-only tickets, missing bindings and failed operations reject.

For cached native lineage in a later operation, explicitly rebind only after obtaining the current owner's actual snapshot and confirming the same backing RDD and output. A historical weak-map entry or schema alone cannot attach a new owner. RDD scans expose their actual `rdd` and output for comparison. [Spark 3.5.4 ExistingRDD, `LogicalRDD`, `RDDScanExec`](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/ExistingRDD.scala).

A fully native physical plan is left structurally unchanged. Its ticket establishes metadata origin; this document does not claim general revocation of retained native RDDs or raw execution. User receipt validation remains at its logical planning boundary and collection root. Native handling must not recursively run the user's complete validator while that validator itself performs native metadata checks.

## 5. AQE and cache decisions

Check user `spark.sql.adaptive.enabled` in the typed logical user path before native scan preparation and again in physical admission/collection validation. Reject with a specific unsupported-user-AQE error even when Spark would decide a particular projection needs no adaptive wrapper. Never call `conf.set`, rewrite the session setting, or reject typed native metadata just because its session has AQE enabled.

For native AQE, inspect `AdaptiveSparkPlanExec.inputPlan` at the outer callback and `QueryStageExec.plan` at stage callbacks, with cycle detection and explicit reused-exchange handling. Native logical query-stage replacements must retain an association with the already bound stage subtree. No `materialize`, `execute`, `prepare`, `toRdd`, reflection or private Spark package adapter may be used to discover provenance. A callback over a native exchange validates and returns that exchange, preserving Spark's required root type. Any user/mixed stage rejects.

Reject every user `InMemoryRelation` in the post-cache-substitution logical plan, including nested hits; reject `InMemoryTableScanExec`/other user cache scan substitutions physically, even if they carry copied user receipts. Also reject a cache stage hidden inside an adaptive/native wrapper unless there is a separately qualified native route. The existing Delta metadata cache uses persisted RDD lineage, not a blanket Spark SQL table-cache exemption. Leave cache settings and Delta's native RDD persistence enabled. Cache rejection is the contract, not secure user cache reuse.

## 6. Collection guard implementation contract

Use a visible `DeltaRangerCollectGuardExec(child)(driverContext)` with only `child` in its product/expression surface. Keep the context transient and omitted from plan string/JSON output; use ordinary `otherCopyArgs`/`withNewChildInternal` support so Spark copies retain the driver context and revalidate the replacement child. No global strong plan registry. A deserialized guard without its driver context and a canonicalized guard must fail closed. Verify that task closures reference only child RDD operations, not the receipt or validator.

`executeCollect` runs, in order: driver/canonicalization check, final child/provenance check, complete parent receipt validator, then `super.executeCollect()`. It does not call the child's preparation, collection, RDD or metric access with side effects before validation. Preserve child output, ordering and partitioning; use a row-based root after the post-transition callback, since the normal executed-plan pipeline requests row output. Native vectorized scans remain visible below their normal conversion nodes.

Keep validation in `doExecute` as defense in depth, then delegate to `child.execute()`. If columnar execution is implemented as a secondary path, validate in `doExecuteColumnar` as well and forward support consistently; it adds no supported action claim. The essential boundary is the `executeCollect` override. `executeCollectPublic` already dispatches through it. Inherited visible-child cleanup/reset traversal remains intact. No direct protected cleanup call on an arbitrary delegate is required. [Spark 3.5.4 SparkPlan, collection, preparation and lifecycle methods](https://raw.githubusercontent.com/apache/spark/v3.5.4/sql/core/src/main/scala/org/apache/spark/sql/execution/SparkPlan.scala).

Do not promise that Dataset cleans up on every action; the mechanics report only proves explicit inherited cleanup traversal. Do not claim raw physical `execute`, `executeColumnar`, `prepare`, `QueryExecution.toRdd`, Dataset RDD APIs, iterator acquisition/consumption, arbitrary actions or running-action cancellation. A publication after the admitted collection boundary need not cancel the already started action. Separate collection-entry validation counters from any defense-in-depth checks.

## 7. Finite integration gate

Extend the existing tests rather than replacing the real native controls with synthetic Boolean tests. Run this gate only in the authorized implementation/qualification stage; none was run for this document.

1. **Production installation and unchanged collection:** real named Delta projection and filter through the production extension; retain the same Dataset and executed root; repeated `collect`/`collectAsList` return exact unchanged rows. Assert one outer guard, visible codegen child, real row and vectorized scans, and repeated entry into the complete validator.
2. **Stale before first/reused collection:** use deterministic full-receipt invalidation before collection; guard-specific denial and zero new child prepare/execute/scan counts. Preserve unchanged controls. Include a real two-catalog `BroadcastHashJoinExec`/`BroadcastExchangeExec`, stale on either engine/binding, and retain both sides' original obligations. A generic unsupported-shape error is not this test's success.
3. **Prepared-index binding:** assert original index differs from prepared index; exact mapping admits the real scan. Different prepared index with the same path/snapshot UUID, copied root/leaf tags, changed output/occurrence and an ordinary Parquet scan reject. Include a self-join and qualified exchange reuse without losing duplicate receipt obligations.
4. **Delayed native classification:** capture a valid native logical query while a real owner scope is active, close the scope successfully, then force physical planning and execute the finite native metadata query. Cover JSON log read, checkpoint read, state reconstruction, exact state/stats cached RDD, native aggregate and analysis-only binding. Confirm there is no user guard on native roots. A copied candidate or failed-scope ticket rejects. Binding alone never reaches execution.
5. **Reentrant RDD capture:** instrument state/stats getter analysis to observe pending status; attempting physical admission before sealing rejects. The actual returned RDD seals and works; a different same-schema RDD, altered ExprIds/nullability/qualifier, different snapshot/index, or cross-session copied ticket rejects. Include reuse of a real native cache under a fresh explicitly rebound owner.
6. **Native spoof matrix:** carry forward all exact aggregate/encoder negatives in `TestDeltaRangerNativeSnapshotAdmission`. Add copied tags to user Delta, ordinary JSON/Parquet, foreign native log index, forged same-schema state/stats RDD, changed object-function instance and mixed native/user join. Preserve the existing unfiltered projection and current valid fresh-query controls.
7. **AQE distinction:** leave AQE enabled in the test session; genuine native reconstruction/aggregate with exchanges succeeds with exact stage root types. A user named SELECT rejects specifically for unsupported AQE and the effective setting remains true afterward. Repeat user denial after retaining a plan and changing the setting. Prove missing/mixed native stage evidence rejects rather than bypasses.
8. **Cache distinction:** populate a user cache in a fixture, then test full and nested substitution plus copied receipts; reject logically and physically with explicit cache/provenance errors. With caches still enabled, real Delta state/stats RDD caching remains valid. Do not disable cache/AQE options to manufacture the control result.
9. **Copy/lifecycle:** normal Spark clones and codegen/reuse tail passes preserve the actual guard root and verified child; altered `withNewChildren` substitution rejects. Explain/JSON/task-closure inspection contains no receipt/engine/principal payload. Explicit cleanup after success, denial and admitted downstream failure reaches real children; collected results are unchanged.

Suggested test placement: retain `TestDeltaRangerCollectBoundary.scala` as mechanics evidence; add `TestDeltaRangerPhysicalAdmission.scala` and `TestDeltaRangerNativeProvenance.scala`; extend `TestDeltaRangerNativeSnapshotAdmission.scala` and the real native SELECT fixture. The full engine/registration/decision stale matrix belongs to the root production receipt slice. After bounded local success, run the approved four Spark/Delta pairs and real Ranger qualification separately.

## 8. Acceptance blockers and limits

The public injection/collection override mechanics are already proven on the two reported diagonal profiles. No source-backed impossibility was found for that narrow boundary. This design does **not** establish that all native propagation details compile or pass on all four profiles.

Before production integration is accepted, implementation must close three concrete gates: (a) exact state/stats RDD capture and sealing without circular execution during getter analysis; (b) finite native optimizer/AQE witness propagation, including hidden stage subtrees and exchange root preservation; (c) user physical witness validation across prepared-index replacement, codegen and exchange reuse. A generic native node allowlist plus copied marker does not close any of them. If an exact native transformation cannot be verified with the exposed fields, reject that transformation and record the resulting unsupported route; do not silently widen native admission or claim the current fresh-query surface is preserved until its positive test passes.

Initial native load scope is mandatory: adding only `injectColumnar` and the existing `registerSnapshot` cannot cover log work triggered by the base catalog's `headCheck`/native load/descriptor materialization. Operation ownership must therefore land with the registration binding integration. Task 4 stays open until those production and qualification gates pass.
